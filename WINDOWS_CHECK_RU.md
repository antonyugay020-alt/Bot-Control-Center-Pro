# Одна проверка на Windows

Это проверочный пакет PAPER, не готовый релиз. Настоящие ордера не отправляются.
Ключи бирж и доступ к аккаунтам не нужны.

1. Распакуйте ZIP целиком в новую папку. Не переносите туда прежние MY_BOTS.
2. Запустите **CHECK_WINDOWS.bat**. Нужен установленный Python 3.10 или новее
   (рекомендуется 3.12) и интернет. Зависимости установятся автоматически в
   отдельное окружение; ваши другие проекты и боты не изменяются.
3. Дождитесь проверок. Затем автоматически откроется Modern Qt с пустым списком
   ботов. Создайте VELES с вашими условиями: несколько монет, секции, вход 2m,
   выход 1m либо другие выбранные интервалы. Проверьте сохранение, редактирование,
   запуск, реальные свечи, сигналы, входы, DCA и выходы. Если сигнал не появился,
   это ожидание, а не подтверждённая сделка. Остальные сценарии перечислены в
   ACCEPTANCE_WINDOWS_RU.md; их результат не отмечается автоматически.
   Для одновременного наблюдения нажмите «Монитор всех ботов» в верхней панели.
   Изменяемые параметры VELES находятся на шагах конструктора; «Просмотр
   параметров» в главном окне показывает сохранённые и действующие настройки.
4. Закройте оболочку. В консоли R повторно открывает её с теми же работающими
   ботами — так проверяется восстановление управления после закрытия окна.
   Для окончания нажмите Enter. Проверка остановит только ботов ЭТОГО сеанса,
   сохранив позиции, историю и файлы в `check_workspaces`. Дождитесь сообщения
   **REPORT** в окне проверки.
5. Пришлите сюда созданный рядом с CHECK_WINDOWS.bat архив
   **BCC_VALIDATION_RESULTS_….zip** и кратко напишите, что не сработало.

Архив собирается и при ошибке установки или проверок. В нём: системные сведения,
результаты тестов, снимки самой программы, доступность API, конфигурации, журналы
и PAPER-состояние только тестовых ботов. Другие папки компьютера не собираются.
Для проверок процессов сохраняются PID launcher и worker, результат независимой
проверки ОС и журналы дочерних процессов, в том числе при ошибке запуска.
При отклонении времени стакана Polymarket отчёт дополнительно сравнивает
время публичных API Polymarket, Bybit и Binance с часами ПК. Точная торговая
опора строится из согласующихся интервалов Bybit и Binance; её параметры
сохраняются в отчёте источников. Время Windows и допуск стакана не меняются.
До окончания проверки оставляйте консоль открытой. Архив формируется после
закрытия программы; аварийное выключение компьютера может помешать сборке.

Для сохранения текущих PAPER-позиций используйте полный экспорт и импорт
по RECOVERY_RU.md. Старая копия перед переносом должна быть остановлена.
Если уже открыта старая оболочка,
её можно оставить: этот запуск использует отдельные каталоги и собственные счета.
PAPER-циклы на живых данных и ручные действия требуют наблюдения; зелёный
автоматический отчёт сам по себе не подтверждает готовность программы.

В пакете 07 исправлена сверка времени и добавлен приоритет открытых позиций
при большом списке монет. Для проверки оставьте PAPER-бота работающим хотя бы
до закрытия сделки; несколько секунд подтверждают лишь запуск. Если условия
выхода не наступили, полный цикл остаётся неподтверждённым.

Пакет 08: исправлена конкуренция общей базы кэша, причины остановки видны
в главном окне и отчёте. Остановленные боты с открытыми позициями остаются
в мониторе, с пометкой о приостановленном сопровождении.

Пакет 09 уменьшает задержки обработки большого числа монет. Проверяйте не
только работающий процесс: в мониторе должны обновляться данные позиций,
ручное закрытие должно появиться в истории как исполнение, а не остаться
ожидающим. RUNTIME_PERF в журнале показывает обработку и работу кэша.

## Отчёт работающих ботов без остановки

В окне, где видны ваши боты, нажмите «Сохранить отчёт». Если открыто пустое
окно новой сборки, выберите прежнюю папку программы с MY_BOTS. Если бот был
создан при CHECK_WINDOWS.bat, выберите соответствующий каталог внутри
check_workspaces, непосредственно содержащий MY_BOTS. Для выбора другой
папки есть пункт «Перенос → Отчёт другой папки без остановки».

Сохраняется BCC_CURRENT_REPORT_....zip. В этот отчёт попадают данные выбранных
существующих ботов, а не только новой проверочной папки. Процессы продолжают
работу. Пустой отчёт не создаётся: при неверной папке выберите нужный каталог.
Присылайте этот ZIP для диагностики текущих позиций. Автоматический
BCC_VALIDATION_RESULTS_....zip сохраняет отдельные результаты проверки сборки.
