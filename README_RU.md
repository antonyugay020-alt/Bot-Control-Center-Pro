# Bot Control Center Pro

Windows-программа для создания и управления торговыми ботами. Проект переписан
по требованиям текущего диалога. Старый handoff используется как справочный материал.
Статус проверки указан в STATUS_RU.md; готовность релиза пока не подтверждена.

## Два этапа проекта

1. **PAPER:** настоящие публичные котировки, свечи, стаканы и исходы рынков;
   виртуальные исполнения и отдельный сохраняемый счёт каждого бота.
   Программа не отправляет биржевые ордера и не запрашивает ключи доступа.
2. **LIVE:** подключение биржевых аккаунтов и исполнение тех же торговых решений
   настоящими ордерами. Этот этап ещё не реализован. Переключить текущую
   PAPER-конфигурацию в LIVE нельзя.

## Запуск на Windows

Для единой проверки пакета используйте **CHECK_WINDOWS.bat**: окружение,
автоматические проверки, отдельный запуск программы и ZIP с результатами.
Порядок действий — WINDOWS_CHECK_RU.md. Старые боты автоматически не импортируются.

1. Установите Python 3.12 с Python Launcher (`py`).
2. Распакуйте проект в отдельную новую папку.
3. Запустите INSTALL.bat, затем START.bat.

INSTALL.bat создаёт отдельное окружение `.venv` в папке этой установки;
общесистемный Python и MY_BOTS не изменяются. START.bat сначала проверяет
необходимые зависимости в `.venv`, затем открывает единственную оболочку
Modern Qt без консольного окна. Если установка или проверка зависимостей не
прошла, START.bat показывает ошибку и не запускает невидимый неисправный GUI.
При ошибке после запуска подробности находятся в
`%LOCALAPPDATA%\BotControlCenterPro\startup.log` (резервный путь —
`%TEMP%\BotControlCenterPro\startup.log`). Зависимости — requirements.txt.

**Обычный запуск без Codex:** для открытия Qt-программы используйте только
`START.bat`. При первом запуске он создаст приватное окружение и установит
зависимости, если это необходимо. Если окно не появляется, используйте
`START_DIAGNOSTIC.bat`: он запускает то же приложение с видимым traceback,
а также сохраняет журнал в `%LOCALAPPDATA%\BotControlCenterPro\startup_console.log`.
`AI_CYCLE_WINDOWS.bat` не запускает программу; это отдельный, необязательный
режим разработки, который может быть заблокирован настройками Codex.
Сборка остаётся внутренней: полная Windows Qt E2E-приёмка не подтверждена.

## Создание и управление

Нажмите «Новый бот», выберите стратегию и пройдите шесть страниц конструктора.
Для Bybit список содержит торгующиеся бессрочные USDT-контракты. Однобуквенные
и Unicode-символы поддерживаются. Ошибки дубликатов и формата различаются и
показывают конкретные обозначения. Черновик из другой папки открывается через
«Перенос → Открыть черновик бота»; он сохраняется как новый независимый бот.
Тот же конструктор используется для редактирования. Бот сохраняется отдельно
от его запуска. Незавершённые настройки можно сохранить в черновик.

Боты находятся в `MY_BOTS/<стратегия>/<идентификатор>/`. Имя, включая русское,
задаётся в интерфейсе. Дерево слева и таблица показывают одни и те же папки.
Сортировка таблицы сохраняет идентичность выбранного бота.

Кнопка **«Монитор всех ботов»** открывает отдельное немодальное окно.
Оно показывает работающих ботов всех стратегий независимо от фильтра главного
окна: heartbeat, баланс, капитал, свободную маржу, PnL, позиции, сигналы и
последние исполнения. Остановленные боты добавляются отдельным переключателем.
По двойному щелчку открывается выбранный бот в главном окне. Закрытие монитора
не останавливает процессы. «—» вместо оценки означает отсутствие свежих данных.

- **Запуск:** отдельный процесс, собственные настройки и PAPER-счёт.
- **Стоп:** прекращает обработку; сохраняет позиции, ожидающие сетки и историю.
  Пока процесс остановлен, он не выполняет защитные выходы. После запуска
  обработка продолжается по новым публичным данным.
- **После сделок:** запрещает новые сделки, продолжает управление открытыми
  позициями и ранее ожидающими сетками; после их завершения останавливает
  процесс. Незавершённая команда сохраняется при перезапуске. Через контекстное
  меню завершение можно отменить. Автоматический вариант задаётся в конструкторе:
  у нового пустого бота завершение начинается после первого полного выхода,
  а при запуске с имеющимися сделками — сразу.
- **Принудительная остановка:** завершает только подтверждённый процесс бота;
  последняя завершённая транзакция сохраняется.
- **Настройки:** доступен просмотр файла на диске, действующего снимка процесса,
  последнего запуска и зафиксированных параметров открытых позиций.
  Внутри просмотра есть обновление, время снимка, копирование и безопасный экспорт.
- **Редактирование:** доступно после остановки. Изменения общих параметров
  применяются к новым сделкам; параметры уже открытых позиций сохраняются.
- **Копия / перенос:** только настройки либо также баланс, позиции, история,
  статистика и журналы. Каждая копия получает независимую папку и счёт.
- **Удаление:** отдельное подтверждаемое действие; при открытых позициях запрещено.

Переключатель запрета новых входов сохраняет управление уже открытыми позициями.
Ранее выставленные ожидающие сетки также продолжают обрабатываться по своим
сохранённым параметрам; отключение монеты или секции не отменяет эти заявки.
Для отмены ожидающих сеток используйте действие закрытия PAPER-позиций.
Отключение секции предотвращает её следующие входы. Остановка процесса и
закрытие позиции — разные операции. Ручное закрытие PAPER-позиций требует
работающего бота и свежего стакана; неисполненный остаток сохраняется.

## Стратегии

**VELES.** Несколько монет и независимых секций в одном боте. Генератор создаёт
цепочки диапазонов RSI; для каждого входа и выхода выбираются индикатор, период,
таймфрейм, уровень и направление пересечения. Доступны 48 выходов индикаторов,
сравнение двух индикаторов, сдвиги, вложенные группы И/ИЛИ. Вход 2m и выход 1m —
пример настройки, оба значения изменяются. При разных таймфреймах секции могут
перекрываться. При общем сигнале выходы обрабатываются раньше новых входов.

Доступны DCA «Простой / Свой / Сигнал», веса и уровни сетки, частичное размещение,
логарифмические цены, мартингейл, отступ и подтяжка; сигнальный или обычный TP,
мульти-тейки, безубыток, трейлинг и SL. Общие параметры наследуются монетами
и секциями; индивидуальные изменения можно применить к выбранным монетам
либо сбросить к общим.

Для каждой монеты можно отдельно менять направление и включение секции.
Редактирование её ордеров не закрепляет неизменённые сигналы: они продолжают
наследоваться. Предпросмотр выбирает монету и секцию, учитывает SHORT/LONG,
индивидуальное плечо и объём сетки; цены показаны относительно условной базы 100.
Маленький частичный тейк, не проходящий биржевой шаг, переносится в следующий
тейк без фиктивного исполнения. Остатки округления учитываются в следующих уровнях.

Реинвестирование VELES добавляет выбранные 0–50% положительного результата
завершённой сделки после торговых комиссий, без funding; незакрытый результат
и убыточные циклы депозит не увеличивают. Процентный и сигнальный стопы
могут работать вместе. Процентный отступ прибавляется к перекрытию от общей
базы сетки: перекрытие 15% и SL 5% дают границу 20% от базы. Для сигнального
усреднения используется фактический последний вход. Можно остановить секцию
после исполнения SL.

**Polymarket.** UP/DOWN по монетам и длительностям рынков 5/15/60 минут при
фактической доступности. Для комбинации монета × длительность задаются импульс,
ASK-коридор, окно входа, размер ставки и отключение. Импульс вычисляется по
Binance spot; выплаты определяются исключительно официальным исходом Polymarket.
Позиция удерживается до исхода. Комиссии берутся из публичной схемы рынка
либо из явно выбранной оценки. Старые автономные PM-боты не импортируются.

**PUMP&DUMP.** Импульс цены и относительного объёма по закрытым минутным свечам;
последующий отскок отслеживается по котировкам. Быстрый и подтверждённый режимы
имеют отдельные позиции, TP, SL и время удержания. Начальные 4% за 3 минуты
и объём 3× изменяются в конструкторе.

**GRID.** Несколько монет, LONG/SHORT, уровни, шаг, номинал ордера и TP/SL
каждого уровня. Также доступны EMA, MACD, Bollinger Bands и EMA + RSI + Volume
с редактируемыми условиями.

## Реалистичность PAPER

Исполнение использует доступную глубину публичного стакана, шаг количества,
минимальный объём, комиссию и заданное проскальзывание. IOC исполняет доступную
часть и отменяет остаток заявки; остаток закрываемой позиции остаётся задачей
на последующие свежие котировки. FOK отклоняет недостаточно обеспеченное
глубиной исполнение целиком. Один снимок ликвидности расходуется секциями совместно.

Общий капитал резервируется под позиции и будущие DCA. Открытый убыток уменьшает
свободную маржу. Журнал исполнений и финансовое состояние фиксируются одной
SQLite-транзакцией; проверка баланса блокирует запуск повреждённого счёта.
Ограничения на число открытых позиций «20» нет.

Публичные данные опрашиваются примерно раз в две секунды с ограниченным
параллелизмом и общим кэшем. Это не биржевой matching engine: очередь лимитных
ордеров, задержки частного API и все правила реальной ликвидации не воспроизводятся.
Funding использует опубликованную ставку и минутную оценку mark-price;
запоздавшая публикация учитывается и после закрытия сделки. Текущий источник
funding запрашивает последние 50 событий; восстановление после более долгого
перерыва требует отдельной сверки. Maintenance margin — упрощённая оценка без
биржевых тарифных ступеней. Частота опроса может пропускать короткие внутрисвечные
движения. Совпадение формул и сигналов со всеми закрытыми индикаторами VELES
не подтверждено.

## Проверка

VALIDATE_WINDOWS.bat в отдельном `.check_venv` устанавливает зависимости и запускает тесты,
настоящий Windows Qt и проверку публичных источников. Отчёт и снимки сохраняются
в verification_reports. Затем выполните ACCEPTANCE_WINDOWS_RU.md на живых
публичных данных. Автоматический отчёт не объявляет сборку готовой к релизу.

Отдельная диагностика сети: `py -3 -m bcc.health`. Для разработчика на Linux:
`python -m pytest -q`; `python -m bcc.gui_check --offscreen --output <папка>`.
Offscreen-отрисовка не заменяет нативную проверку Windows.

Согласованные требования: REQUIREMENTS_RU.md. Устройство проекта и второй этап:
ARCHITECTURE_RU.md. Основные справочники: https://help.veles.finance/ru/,
https://bybit-exchange.github.io/docs/v5/intro, https://docs.polymarket.com/.

## Свежесть стакана — пакет 11

Для исполнения используется исходный Bybit result.ts или timestamp CLOB. Время
получения HTTP-ответа не заменяет время стакана. Допуск: возраст не более 3 секунд
по верхней границе сверенного UTC; допустимое опережение — не более 0,5 секунды
по нижней границе. Проверяются источник, очередь решений и окончательное исполнение.
Если снимок успел устареть во время расчёта, объём не расходуется, исполнения нет.

OPEN/DCA/CLOSE/PARTIAL сохраняют book_at, book_age_lower и book_age_upper.
В «Сохранить отчёт» включается сводка execution_freshness. Старая история без этих
полей отмечается PARTIAL_EVIDENCE, а не считается проверенной задним числом.
Сообщение об отказе показывает интервал возраста и допуск. Для Bybit дополнительно
фиксируются HTTP/кэш, время получения и разница между временем ответа и стакана.

Котировки для оценки PnL имеют отдельный срок 15 секунд. Он не разрешает исполнение
по стакану старше 3 секунд. Монотонная метка и проверка скачка часов исключают
ложную свежесть сохранённой оценки после изменения времени ПК. Часы ОС не меняются.

Повторная регрессия разработчика: python tools/audit20.py. Она выполняет 20 полных
прогонов с различными фиксированными seeds. Сетевые источники и нативный Windows
проверяются отдельно через CHECK_WINDOWS.bat.
