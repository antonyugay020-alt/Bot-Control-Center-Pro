# RUN25 — единая транзакция конструктора VELES / Polymarket (внутренний checkpoint)

Создан `bcc/constructor_transaction.py` — единый, не выполняющий торговлю слой для комплексного редактирования общих настроек риска, секций VELES, монет, длительностей Polymarket, глобальных правил, индивидуальных правил монет и рынков. Сначала формируется полная копия кандидата, затем проверяется только итоговая комбинация; промежуточное состояние не применяется. Это допускает согласованные изменения нескольких взаимозависимых параметров за одну операцию и отвергает итоговые ошибки без частичных изменений.

Два отдельных представления: workspace сохраняет временно выключенные монеты/рынки и их `entry_seconds_before_close`, а `validate_constructor_publish` отбрасывает неактивные комбинации и проверяет полный сериализованный набор фактических правил до вызова пользовательского `on_save`. `BotWizard.commit` теперь использует этот общий контракт. Сохранение черновика остаётся отдельной ревизионной транзакцией и допускает незавершённое имя; публикация требует корректную полную конфигурацию.

Проверки включают случай, когда изменение защитного порога Polymarket само по себе недопустимо, но вместе с корректировкой рынка допустимо; VELES: изменение ID диапазона одновременно с индивидуальными настройками монеты; сохранение/повторное открытие/редактирование через Repository; сохранение dormant-правил; рандомизированные тесты. Добавлены два новых нативных Qt E2E-сценария в `tests/test_constructor_full_commit_qt_run25.py`, но они НЕ выполнены без PySide6/Windows.

Проверка SQLite PAPER проводится отдельно, строго только для чтения. Живые настройки, worker, ордера и PAPER-счета не затрагиваются. Полная Windows Qt E2E-приёмка не выполнена. Выпуск запрещён.
