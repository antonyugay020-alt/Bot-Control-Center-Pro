# Актуальная архитектура BCC: внутренний рабочий checkpoint (не релиз)

Канонический маршрут: Modern Qt → Supervisor → Coordinator → RuntimeService → Fleet → Lifecycle → Worker → Store.

В этой копии операции создания, редактирования, копирования, импорта, запуска, остановки и удаления проходят через единый контроль. Редактирование и копирование с общей PAPER-историей дополнительно входят в межпроцессный per-bot барьер команд/финансовых транзакций: STOP, retirement и операции одного счёта взаимно упорядочены, разные счета не блокируют друг друга. Строгая регистрация не допускает retiring owner. Тесты охватывают одновременные edit/copy ↔ retirement, позднюю регистрацию и независимый STOP другого бота.

Не закрыто: полная регрессия на одном непрерывном запуске не подтверждена — тестовые worker/hub процессы иногда удерживают отдельные группы; Windows Qt E2E не проводилась (в текущем Linux отсутствует PySide6/Windows). Релиз запрещён, готовность всей архитектуры не утверждается.

## Контроль экспортной границы, 2026-11-03

Пользовательский экспорт в Modern Qt переведён через Supervisor.export_bots. Внутри transfer.export_bots снимок каждого владельца удерживает тот же межпроцессный gate, что STOP, retirement, редактирование конфигурации и PAPER commit. Конкурентные тесты подтверждают ожидание STOP до конца снимка и отклонение экспорта retiring-владельца. Прямой низкоуровневый вызов transfer.export_bots оставлен для совместимости; канонический UI использует Supervisor. Нативная Windows Qt E2E не выполнена.

Текущая проверка новой копии: 1179 headless PASS в одном прогоне, 6 реальных process tests PASS отдельно. Windows Qt E2E не выполнялась.

## Сквозная граница чтения и переноса, 2026-11-03

Функция экспорта CSV из Modern Qt больше не читает Store напрямую:
`Supervisor.export_history_csv` удерживает общую межпроцессную защиту владельца,
проверяет статус retirement, сериализует историю и атомарно публикует целевой CSV.
Локальный исходный бот при импорте ZIP теперь проверяется через тот же барьер
Supervisor, что STOP/retirement и финансовые коммиты. Обработчик Qt вызывает
новый маршрут Supervisor. В регрессию добавлены проверки STOP во время CSV-
снимка, запрета CSV для retiring owner, запрета импорта retiring source и
защиты путей внутри MY_BOTS.

Контроль: новые и смежные сценарии проходят (9/9). Единый непрерывный headless
прогон не завершён в доступном времени (задержался на реальном replay-worker).
Нативная Windows Qt E2E не выполнена. Это внутренний checkpoint, не релиз.

Итог повторной регрессии после синхронизации SHA-256: 1189 headless-тестов
в одном непрерывном прогоне — PASS (159.80 s). Windows Qt E2E здесь
не выполнялась: PySide6 отсутствует, ОС Linux. Релиз по-прежнему запрещён.

## Контракт нативной приёмки — контрольный checkpoint

Проверка Windows теперь требует подтверждённый цикл Qt для VELES, GRID, PUMP_DUMP и POLYMARKET: копия, ZIP-перенос, CSV, отзыв команды, удаление, независимость и аудит PAPER. Проверка запрещает считать START/STOP в виде записи команды реальным подтверждением работающего worker. 112 смежных тестов пройдены, однако единый headless-прогон завис в процессной группе; нативная Windows Qt E2E не выполнялась. Релиз запрещён.

## Проверка 2026-11-03 — единый force-stop

В ветке Lifecycle.stop(force=True) при подтверждённом Popen-launcher ранее Windows использовал проверку токена и дерева процессов, а POSIX убивал лишь launcher. Теперь обе платформы используют одну проверку владельца по токену и папке и остановку потомков до launcher. Защитные тесты при неверном токене запрещают убивать чужой процесс. 38 смежных тестов прошли, включая реальные worker-процессы. Общий монолитный headless-прогон не прошёл (отказ и зависание около 36%). Windows Qt E2E не выполнялась. Релиз заблокирован.


## Этап: фоновый монитор Modern Qt — инженерная интеграция

Снимки SQLite/процессов получаются в единственной фоновой задаче с объединением запросов. При закрытии окна увеличивается поколение запроса: запоздалые результаты больше не подменяют данные повторно открытого монитора. Ошибка чтения не оставляет прежний статус «Работает».

Совместный прогон 21 теста завершён успешно (5 архитектурных тестов монитора и 16 процессных/запусковых). Этап кода передан на нативную Windows Qt E2E-приёмку; полный релиз не подтверждён.

## Внутренний checkpoint RUN22: черновики редактирования существующих ботов

Конструкторы VELES и Polymarket получили отдельный путь сохранения несохранённых
изменений существующего бота. Путь черновика однозначно привязан к владельцу
MY_BOTS и SHA-256 его исходного config.json. При изменении конфигурации другим
окном или процессом старый черновик не подставляется в редактор новой версии.
Два окна используют revision-CAS из constructor_session; повреждённый или
чужой черновик не заменяется настройками по умолчанию. Если пользователь
отказывается продолжать уже сохранённый черновик, редактор открывает текущую
конфигурацию без права перезаписать черновик другого окна.

Сохранение черновика не вызывает Supervisor, Repository.save, Worker и
операции PAPER. Окончательная публикация изменений проходит только через
Supervisor.save_bot с первоначальным digest, остановкой бота, проверкой
конфликта и финансовыми барьерами. Ручное «Открыть черновик бота» не может
импортировать edit-workspace как нового бота. Все торговые поля, включая
entry_seconds_before_close, остаются в исходной схеме и проверяются общим
контрактом конструктора.

Это инженерная реализация, а не подтверждение нативного Qt-поведения:
PySide6 и Windows Qt E2E недоступны в текущей Linux-среде. Релиз запрещён.
