# Bot Control Center Pro — интеграция 04.11.2026

Рабочая копия объединяет полезные изменения двух присланных веток Windows QA
с ранее сохранёнными маржой, ступенчатой PAPER-ликвидацией и общим риском.
Основания выбора и причины отказов: INTEGRATION_REVIEW_RU.md.

Проверки текущего fingerprint сохраняются отдельно как JUnit и отчёт checkpoint.
Предыдущие числа PASS из BUILD_INFO/VALIDATION_STATUS — исторические результаты
входной ветки; они не подтверждают этот изменённый код.

Текущая Windows Qt E2E и реальный публичный PAPER не подтверждены. Выпуск
заблокирован до полной приёмки. Пользовательские счета и настройки не менялись,
реальные ордера не отправлялись. LIVE относится к следующему этапу.

Общий слой process_os устраняет неоднозначность PID между Popen, /proc и
сигналами ОС. Проверки создания/пути/токена сохранены; неизвестная личность
по-прежнему блокирует операции. Процессные проверки и очистка QA используют
тот же системный провайдер. Текущие результаты берутся из нового полного JUnit,
а не из прежнего отчёта с 21 отказом. Нативная Windows-приёмка ещё обязательна.

Сохранение общих лимитов теперь упорядочено с START/STOP через Coordinator:
принятый запуск блокирует изменение, смена ревизий во время проверки требует
повторного сохранения, обход ОС не занимает writer и не задерживает STOP.
Новый полный прогон проверяет эту версию целиком, включая прежние функции.

Групповой импорт удерживает командные и worker-блокировки всех местных исходных
ботов до общей публикации или полного отката. Порядок блокировок учитывает
полосы Supervisor и ключи ОС, поэтому повторяющиеся исходники и встречные
пакеты не блокируют сами себя. Ожидающий START запрещает редактирование,
копирование и экспорт так же, как реально работающий процесс.

Новые PAPER-циклы имеют идентификатор позиции в состоянии и исполнениях.
Транзакции сверяют количество, среднюю цену, комиссию, маржу и денежные
движения; восстановление, копирование и импорт независимо повторяют журнал
в порядке SQLite commit. Funding после закрытия остаётся привязан к своему
циклу. Polymarket сверяет shares/cost/fee и официальный SETTLE. Старые счета
без идентификаторов продолжают прежний денежный аудит: для них не создаются
вымышленные исторические исполнения. Результат текущей общей регрессии
сохраняется рядом с точными исходниками; Windows и публичный PAPER остаются
самостоятельными обязательными этапами.

Зафиксированные настройки/план сетки и данные исхода защищены digest открытия.
Отдельно сверяются накопленные расходы, исходный объём и результат частичных
выходов/закрытого цикла. Для новых сделок ключи funding используют ID цикла,
а не сочетание монеты и времени: одинаковые timestamps не объединяют сделки.

Интерактивная приёмка теперь сама владеет своей службой до запуска Qt и
использует новое приватное хранилище. R повторно открывает окно без остановки
ботов; завершение сеанса подаёт Stop через Coordinator, сохраняет состояния,
останавливает его Hub и проверяет освобождение host leases. Продакшен-поведение
закрытия Qt не меняется. Отдельный E2E с двумя Qt-интерпретаторами и работающим
PAPER-счётом обязателен в новом Windows gate. Ручной/публичный PAPER остаётся
неподтверждённым до наблюдения соответствующих циклов.

Целостность исходников повторно проверяется между автоматическими этапами,
перед/после интерактивного окна и при завершении проверки. Свидетельство
включает SHA-256 исходного манифеста: изменение кода вместе с его повторным
запечатыванием не позволяет использовать результаты предыдущего этапа.
