# Нативная Windows-приёмка BCC V39

Базовый коммит `51bb3c8d4640e68004e3c6126abbb5595a8f51b9`.
Распакуйте архив в новую папку. Запустите из Windows PowerShell

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\RUN_ACCEPTANCE.ps1 -ReportRoot 'G:\BCC'
```

Нужен установленный Python 3.10+. Скрипт проверяет SHA-256, создаёт отдельное
окружение Python и отдельные каталоги приложения и служебных данных.

1. Самопроверка сценария приёмки.
2. Три реальных прогона через Bybit WS. Каждый создаёт свой Hub.
   Время запуска Hub и ожидания WS-соединений записывается отдельно.
   После подтверждения соединений начинается первый запрос данных с пустым
   кэшем. Все 240 снимков, включая первый раунд, должны уложиться в 1,5 секунды.
   Максимальный возраст данных составляет 3 секунды. Отчёт проверяет
   получение сообщений на обоих соединениях каждого из четырёх шардов и
   отсутствие REST-замещения рыночных данных. HTTP-сверка времени допустима.
3. 543 предварительных теста WS Bybit, Hub версий V24–V39 и изоляции WAL.
4. Отдельная межпроцессная проверка доставки, записи, single-flight и
   жизненного цикла тестовых процессов.
5. Полный нативный набор из 4515 тестов, проверка Qt и публичных источников
   Bybit. В итоговой сводке используются результаты третьего WS-прогона.

Сбой завершает запуск на текущем этапе. ZIP отчёта
`V39_ACCEPTANCE_WINDOWS_*.zip` записывается в `-ReportRoot`.
Главные файлы отчёта — `BOOTSTRAP_SUMMARY.json` и
`ACCEPTANCE/ACCEPTANCE_SUMMARY.json`. Нативная приёмка проверяется запуском
этого пакета на Windows.
