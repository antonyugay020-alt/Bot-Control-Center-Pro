# Автоматическая проверка Windows — без опроса оператора

`tools/run_current_windows_qa.ps1` запускает в новой выделенной QA-папке полную автоматическую регрессию, нативный Qt и проверки публичных источников. После успешного основного этапа сценарий без участия пользователя проверяет публичный Bybit WebSocket (исполняемый стакан и независимый mark-price), затем выполняет ограниченный VELES PAPER-цикл на публичных данных в новом изолированном счёте. Этот счёт управляется `AcceptanceSession`; используются только его собственные worker, runtime и Hub. Реальные ордера и учётные данные не применяются. Невозможность получить сигнал или данные в отведённое время не подменяется тестовыми котировками.

В корне QA-папки создаётся один архив доказательств `BCC_TEST_REPORT_AUTOMATED_*.zip`. В нём `AUTOMATED_ACCEPTANCE_REPORT_RU.txt`, структурированный JSON, результаты и снимки автоматического Qt, копия проверенного JUnit и, если получены, доказательства WebSocket и PAPER. 36 строк содержат статусы связанных групп тестов; связанные тесты не доказывают каждый пункт полного живого сценария. Неподтверждённые части остаются `NOT_CONFIRMED`, релиз автоматически не подтверждается. Полный живой цикл разных стратегий, фактический импульс и официальный исход не возникают по требованию и должны фиксироваться только после действительного наблюдения. При падении основного автоматического этапа публичные торговые проверки не запускаются; отчёт остаётся доступен, если среда Python создана.

Разрешения риска, лимиты и отказ 403/451 не обходятся. При ошибке WebSocket-теста следующий PAPER-тест не создаёт новый кэш и не обращается к тому же источнику повторно. Тест прекращает только процессы, принадлежащие его новой сессии. Выполнение на Linux либо тестовым источником не подтверждает нативный Windows или живую биржу.

Это не доказывает поведение всех монет и не подтверждает живой PAPER-цикл.

PAPER-проверка завершилась `NOT_CONFIRMED`: после постановки команды запуска она прочитала `paper.sqlite` до создания счёта worker. Исправленный сценарий ожидает ограниченное время появления базы и маркера, созданных worker; ранее инициализированный счёт с отсутствующей базой не пересоздаётся. При исключении до завершения теперь также собирается доступный read-only снимок, чтобы не терять диагностику. В регрессии воспроизведён задержанный запуск и выполнен изолированный сквозной цикл с реальным OS worker, контроллером и SQLite на имитированном рынке. Нативный Windows и реальный PAPER для исправленного кода ещё не проверены; полного подтверждения 36 живых сценариев нет.
