## Coordinated implementation

1. PublicCache has one additional **bounded read-only connection per instance**, with its own reader lock; no unbounded per-thread connection pool. Cache hits, bulk portfolios, TTL lookup and provider-denial checks no longer wait behind the local writer. SQLite URI read-only mode and query_only reject writes. Denial plus data/TTL are read from the same transaction; only committed snapshots are visible. Actual expiry, provider denials, quotas, cooldown, and writer admission are retained. Both persistent connections close deterministically. New read operation/connection/contention counters distinguish the lanes.
2. Store still checks **every mutable value and key before and after mutation**. Private keys, nesting and nonfinite values now share one complete traversal. The already validated post-mutation document is not traversed again solely because the method computes its final realized scalar; that derived sum has an explicit finite check, including overflow of finite journal receipts. Position/journal reconciliation, cash reconciliation, execution/control fences, rollback and full reopen/audit validation remain intact. No mutable-state acceptance cache is introduced.
3. Worker health tracks current quote/history failures per symbol separately from cumulative errors. An accepted quote cannot clear an unresolved history fault, another symbol cannot clear it, and a metadata-only tick proves neither channel's recovery. Real failure/recovery transitions publish heartbeat state immediately. UI uses these current failures when available, preserving legacy behavior for old process records. Polymarket's recognized outage/recovery path uses the same reporting contract.

On isolated copies of the same complete native account, seven read + no-op transaction cycles have median **0.266845 → 0.212139 s** (about 20.5% lower).
