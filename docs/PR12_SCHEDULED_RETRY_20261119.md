# PR #12 scheduled recovery and risk-data diagnostic fix — NOT RELEASE

Baseline `c530f8d8147dd4c2a2ec8ce5a2f645cdc36aaaee`. In the user's two sanitized Windows snapshots, the second showed fresh later mark evidence for one held symbol alongside preserved position-level errors from the previous risk calculation; these snapshots are not atomic across worker telemetry and SQLite, so they cannot alone prove the error was current. An independent isolated account reproduced that a fresh mark and tier can leave an old `margin_data_error` until a later liquidation calculation. `refresh_margin_data_diagnostics` now revalidates existing diagnostics on updated observations/tier snapshots. CROSS errors clear only when the same complete `_cross_metrics` data calculation used by liquidation succeeds, including pending grids; ISOLATED positions are checked individually. This operation cannot submit fills, clear liquidation state or bypass the actual entry/risk guard. Tests cover stale/partially recovered/future marks, pending grid failure, isolated positions, risk-only tier recovery and durable ledger continuity.

The first isolated full scheduled WS/Hub/worker experiment at baseline reached 821 of 824 subjects after 480 seconds. Separate scheduling negative control with 824 scanner symbols proved the failure mechanism: one temporary history or book failure was not retried until after the scanner had visited all 824. The existing round-robin cursor makes a periodic due time insufficient to give an already-failed symbol prompt recovery. The scheduler now records failed configured scanner requests in a bounded-concurrency, fair retry lane, interleaved with untouched discovery; it never claims the position quote lane, does not admit entries itself, retains timing/provenance gates and removes queued symbols after configuration removal or priority promotion. Tests cover retry, continuous failure fairness at 1/2/8 workers, the unmarked-position admission pause, and continuing position quotes. Provider denial remains governed by the existing host policy; retries do not grant direct HTTP or stale-price permission. The measured old failure and this fix do not alone prove all prior real Windows incidents had that cause.

`tools/soak_pr12_scheduled_hub.py` is an isolated development harness: fake Bybit socket frames and fake public HTTP payloads, but real WS parsers, subscription management, event dispatcher, Hub registry/leader, shared cache/budget, client, MarketScheduler, `process_tick`, VELES, risk and SQLite. Its temporary workspace is independent; it does not access any real order or user account. It models ten initial candle outages, a shared synthetic 429 cooldown, WS disconnect/generation recovery, a temporary synthetic 403 fence, expired risk-tier and post-recovery entry. Actual external exchange behavior and native Windows remain unproved. The long run and full source-matched regression must be recorded before acceptance; no release, paid actions, merge or Windows restart.

An additional negative control showed that a fleet-wide retry backlog left workers idle under a fixed two-worker retry cap. The cap now expands when no fresh discovery can use that capacity, while retaining a position lane. A regression exercises this case. In the final synthetic run, 824 subjects were processed in 385.4 seconds and ten initially unavailable histories recovered; after the simulated disconnect and provider fences, a fresh risk tier and a continuously valid signal led to a seventh PAPER position without restarting the scheduler, and the ledger audit passed. The complete process took approximately 12 minutes 41 seconds. The preceding run with a 90-second post-recovery deadline failed; it is retained as evidence of slow signal reconsideration at this size, not represented as a pass. The longer run proves eventual entry under this model, not prompt recovery, actual 824-symbol Bybit delivery, or Windows behavior. The simulated 403/429 and WebSocket input are not live provider failures. The risk retry deadline is advanced by the harness, not awaited in real time.

The offscreen Linux partitioned regression completed with 3,965 tests, zero failures, errors or skips against manifest `a6e5f33a16b7c42fc5327b9c66638e1f453b930606df3eb4f74ed6868bf6d290`. A separate isolated public Bybit WS/Hub/client sample passed 24 rounds for 10 symbols, including ADAUSDT, with independently verified fresh book and mark observations; it did not exercise 824 real symbols or the trading engine. The three execution records and the failed short-deadline run are retained under `docs/evidence/pr12_20261119_scheduled/`. These records were added after the tested manifest; the application and test code were not modified after the run. Native Windows automated and manual Qt PAPER acceptance on the resulting commit remain mandatory.
