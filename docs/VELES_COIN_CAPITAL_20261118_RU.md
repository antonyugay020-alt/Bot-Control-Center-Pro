# VELES — единый бюджет капитала на монету (разработка, не релиз)

Исходная продуктовая ветка: `codex/ws-transport-isolated-20261113`,
зафиксированный исходный SHA `7bba4909235cc56e0777075422c705a948eb44c2`.
Рабочая ветка: `codex/coin-budget-unified-20261118`. Ни один работающий бот,
реальная или PAPER-база пользователя, монитор, Market Data Hub не изменялись.

## Что реализовано

Опциональное правило в настройках отдельной монеты VELES:

    "coin_overrides": {
      "BTCUSDT": {"capital_limit": {"mode": "percent", "value": 15.0}},
      "ETHUSDT": {"capital_limit": {"mode": "fixed", "value": 50.0}}
    }

- `percent` — верхний предел номинально выделенного капитала на монету
  от **общего депозита этого бота** `cfg.capital` (не 15% на каждую
  секцию). Диапазон 0.001–100%.
- `fixed` — верхний предел номинально выделенного капитала монеты
  в USDT, от 0.01 до 1e12. Фактическое наличие свободной маржи
  проверяется отдельно; большой фиксированный предел не создаёт денег.
- Отсутствие `capital_limit` — полная совместимость с ранее
  сохранёнными VELES-конфигурациями, без нового ограничения.
- В каждый момент проверяются **все** открытые секции монеты
  (заполненная маржа + обеспечение ожидающих DCA) и отложенные
  лимитные сетки входа. Секции других монет не расходуют её бюджет.
- Новый вход или новая ожидающая сетка блокируются с точным объяснением
  вида: «Лимит капитала BTCUSDT: уже 25 USDT, новая секция 25 USDT,
  предел 25 USDT». Существующие выходы и DCA не блокируются.
- Конвертация уже зарезервированной ожидающей сетки в позицию
  освобождает старую запись перед проверкой: капитал не считается
  дважды. При неисполнении исходная ожидающая сетка восстанавливается.
- Параллельно сохраняются независимые ограничения: общие лимиты
  портфеля, рыночные Bybit tier/mark/funding, фактический свободный
  капитал и проверка стакана. Данный предел — НЕ отдельный
  финансовый кошелёк и НЕ жёсткая оценка ликвидационного риска.

В Modern Qt диалоге «Индивидуальные настройки монеты» сверху
появились выбор «Без отдельного лимита» / «% общего депозита бота» /
«Фиксированная сумма USDT» и числовой ввод. Сохранение, копирование
на другие монеты, сброс к общим и повторное открытие используют
одну транзакционную схему конструктора. Изменения лимита отображаются
в отчёте «Риск и маржа» до сохранения. Если даже одна выбранная
секция сама по себе больше установленного бюджета монеты, её
предпросмотр показывает «вход заблокирован», а не обещает сделку.

## Позиционный лимит

Отдельного жёсткого ограничения на 19 или 20 открытых позиций
в `shared_risk.py` по умолчанию нет: `max_positions=0` означает
выключенную необязательную политику. Если живой бот остановился
на 19 позициях, для доказательства причины нужны реальные
диагностика риск-менеджера, обеспечение, разрешения на вход,
данные Bybit tier и конкретные отказавшие секции; нельзя
объявлять найденным и удалённым несуществующий константный cap.

## Один безопасный нативный Windows запуск

Рабочая ветка — для разработки, а не для непосредственного
запуска установленной торговой программы. Создать отдельный
чистый checkout этой ветки и вызвать из него:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\CHECK_VELES_COIN_BUDGET_WINDOWS.ps1

Скрипт отказывает на неправильной ветке, локальных изменениях
или повторно использованной папке QA. Создаёт уникальную папку
`%USERPROFILE%\Desktop\BCC_COIN_BUDGET_QA_<SHA>` и в ней
закрытый SHA-256-манифестом source ZIP, распаковывает его в новый
подкаталог и запускает только Bybit `-AutomatedOnly` на этом
**изолированном** экземпляре. Новый код ни при каких условиях
не должен обращаться к запущенным пользовательским ботам.
Это штатная полная нативная автоматическая регрессия, включая
отдельный публичный Bybit WS и Qt E2E; сеть нужна только
для установки Python-зависимостей и публичных рыночных данных.
Платные модели и GitHub Actions не вызываются. Если полная
регрессия не зелёная — выпуск заблокирован, отчёт сохраняется.

Один итоговый архив:

    %USERPROFILE%\Desktop\BCC_COIN_BUDGET_QA_<SHA>\LATEST_REPORT.zip

Даже полный PASS автоматического Bybit этапа не подтверждает
длительное сохранение mark-price при уже открытых позициях,
реальное операторское Stop/Restart/reopen и deferred
Polymarket/Binance; их обязательные release-gates остаются.
Не объявлять промежуточную сборку релизом.
