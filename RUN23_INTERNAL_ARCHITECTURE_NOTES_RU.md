# RUN23 — внутренний архитектурный checkpoint (НЕ РЕЛИЗ)

Исходная база: RUN22. Никакие торговые конфигурации существующих ботов, базы PAPER-счетов или процессы worker не менялись.

## Согласованная граница конструктора

Для **редактирования существующего бота** Modern Qt теперь передаёт в общий слой сохранения черновиков идентичность MY_BOTS-владельца и исходный SHA-256 конфигурации. В отдельном JSON-конверте черновика хранится привязка `owner + source_digest`, а исполняемая конфигурация остаётся в `config` без дополнительных торговых полей. Создание нового бота сохраняет прежний формат черновика.

Загрузка черновика другой версии или другого бота отклоняется до отображения настроек. Межпроцессная блокировка, атомарная запись, сравнение ревизий и повторная загрузка применяются к обоим типам черновиков через единый `constructor_session`. Старые черновики редактирования можно мигрировать только после явного подтверждения «Продолжить» в интерфейсе; новая запись сразу включает привязку. Сохранение действующего бота по-прежнему идёт исключительно через Supervisor с исходным digest и штатными проверками блокировок. Параметр `entry_seconds_before_close` остаётся частью эффективной конфигурации глобального, монетного и рыночного уровней.

## Проверки и ограничения

Добавлены 95 тестов с новыми случайными сценариями для VELES и Polymarket: сохранение, возобновление, редактирование, проверка привязки к боту/версии, отказ при подмене черновика, миграция старого формата и отсутствие публикации до явного commit. Это **не** подтверждает завершение всех экранов конструктора.

Проверки Python не заменяют полноценную Windows Qt E2E. На текущем Linux-узле отсутствует PySide6; запуск Qt-зависимых модулей и Windows E2E невозможен. Релиз запрещён до успешной общей регрессии и чистой Windows-приёмки.
