# Bot Control Center Pro — облачная разработка (не релиз)

**Программа BCC остаётся локальной Windows-программой.** GitHub и облачные исполнители предназначены исключительно для кода, проверок и сборки. Эта копия не удостоверяет работоспособность торговых функций.

## Первое размещение

1. В GitHub создайте **пустой приватный** репозиторий `Bot-Control-Center-Pro` без README, .gitignore и лицензии.
2. Подключите к нему ChatGPT/GitHub только с минимально необходимыми разрешениями.
3. В новой папке после распаковки выполните: `git init`, `git add .`, `git commit -m "Import BCC sanitized source and CI"`, `git branch -M main`, `git remote add origin https://github.com/<owner>/Bot-Control-Center-Pro.git`, `git push -u origin main`.
4. В GitHub -> Actions убедитесь, что workflow `BCC source and cross-platform QA` запустился. Ошибки CI — блокеры, а не повод пропускать тесты.

## Границы безопасности

- Не загружайте `.ai_work`, `MY_BOTS`, базы данных, API-ключи, `.env`, личные отчёты, журналы живой торговли и реальную конфигурацию машин.
- Actions не получают секретов или торговых ключей; проверки должны работать на синтетических PAPER-данных.
- `AI_CYCLE_WINDOWS.bat` — прежний локальный механизм разработки, **не требуется для запуска BCC**; `START.bat` — запуск приложения на Windows.
- Настройте branch protection: обязательные проверки двух jobs, запрет слияния при красном CI.
- Финальное принятие требует отдельных полноценных Windows Qt E2E с чистой распаковки на реальном ПК; GitHub runners не заменяют эту приёмку.

## Текущий QA-статус

`BLOCKED / INTERNAL / NOT_RELEASE`. Предыдущий Linux-прогон не прошёл: отсутствовала PySide6 при сборе Qt-тестов, а в частичном headless-прогоне встречались ошибки и падения. Настроенный CI должен показать реальный список дефектов, затем дефекты должны исправляться системно с повторным полным прогоном. До зелёной полной приёмки не объявлять релиз.
