# BCC: команда разработки Codex + локальный Ollama (Windows 11, RTX 3080 Ti)

Эта подсистема организует разработку, **но не является релизом BCC**. Источник — последняя контрольная копия; рабочие боты и PAPER-базы в разработку не импортируются.

## Установка (однократно на компьютере Windows)

1. Установить Git, Node.js LTS (для Codex CLI), Ollama. Проверить `git --version`, `node --version`, `ollama --version`.
2. Установить Codex CLI по официальной документации (обычно `npm install -g @openai/codex`). Выполнить `codex login` и выбрать вход через ChatGPT. При желании можно авторизоваться OpenAI API отдельно; **не хранить и не присылать API-ключ в исходниках или чате**. Платежи API отдельно от ChatGPT.
3. Выполнить `ollama pull qwen3:8b`, затем запустить локальный Ollama. Для RTX 3080 Ti (12 ГБ) начните с Qwen3 8B; фактическая скорость/память проверяются на вашей системе. API должен отвечать на `http://127.0.0.1:11434/api/tags`.
4. В распакованной рабочей копии BCC выполнить INSTALL.bat, затем AI_SETUP_WINDOWS.bat. `doctor` должен показать Git/Codex/Ollama и найденную модель. `init` создаёт отдельный локальный Git-репозиторий и baseline commit. Если Git author identity не настроена, запускатель сам запишет технического автора `BCC Local Automation / bcc-automation@localhost.invalid` **только в локальную `.git/config`**, не меняя глобальный Git. Если предыдущий запуск остановился после `git init` или `git add`, повторный `init` безопасно продолжит создание baseline commit после повторной проверки SHA-256 и индекса Git. Посторонние staged/untracked изменения не удаляются и не коммитятся: в таком случае запуск блокируется с причиной. AI_CYCLE_WINDOWS.bat также самостоятельно проверяет зависимости и выполняет безопасную первичную Git-инициализацию, если она ещё не была выполнена.

## Рабочий цикл

Запустить `AI_CYCLE_WINDOWS.bat` из ЧИСТОЙ копии BCC, без запущенных PAPER-ботов в этом каталоге. Скрипт создаёт отдельную Git-ветку, вызывает Codex с комплексным заданием `BCC_AI_MISSION_RU.md`, запрашивает независимое ревью Ollama, выполняет один согласованный раунд исправления замечаний, собирает **новый проверяемый архив** и запускает `tools.windows_check --automated-only` на чистой распаковке.

Все доказательства и диагностические логи остаются в `.ai_work/<run_id>/`; это локальное игнорируемое Git-хранилище. Не делайте merge в основную ветку, пока не проведена полная ручная и нативная Windows Qt/PAPER приёмка. Любой timeout, пропуск теста, неполное ревью, отказ seal/QA или изменение приватных файлов — **BLOCKED**.

После полного автоматического PASS: отдельно запустить `CHECK_WINDOWS.bat` в проверенном распакованном пакете для ручного реального Qt/PAPER цикла. Сам скрипт AI никогда не маркирует release_ready=true. Готовую сборку формируют только после успешной Windows приёмки без критических дефектов.

## Важные границы

- ChatGPT не может напрямую управлять видеокартой или процессами на вашем ПК. Codex/Ollama запускать **локально**. Наличие связанного GitHub в ChatGPT не устанавливает Codex CLI на Windows.
- Оллама — вспомогательный ревьюер, а не источник финального PASS; 8B-модель может пропустить дефекты.
- Если `codex` не распознан, переоткрыть терминал после установки. Открыть `codex --help`, если версия CLI отличается от примеров.
- Обеспечить копию BCC без живых ключей. `.gitignore` защищает от случайного `git add`, но не делает уже закоммиченные секреты безопасными; перед первым коммитом проверять `git status`.
- Использование GPU для самого BCC не обязательно и допустимо только после профилирования.

## Если BAT окно сразу закрывалось

Запускатели `AI_SETUP_WINDOWS.bat` и `AI_CYCLE_WINDOWS.bat` теперь оставляют окно открытым и сохраняют подробную диагностику в `.ai_work/AI_SETUP_WINDOWS_LAST.log` и `.ai_work/AI_CYCLE_WINDOWS_LAST.log` соответственно. Для запуска из существующей командной строки без паузы установите `set BCC_AI_NO_PAUSE=1`.

При отсутствии `.venv\Scripts\python.exe` нужно сначала запустить `INSTALL.bat`. Если не обнаружены Git/Codex/Ollama или модель `qwen3:8b`, скрипт останавливается с объяснением, не изменяя торговые данные. При ошибке Codex/QА состояние и журналы текущего цикла хранятся в `.ai_work/<run_id>/`. Не удаляйте lock вручную, не проверив работающие процессы.

**Важно:** запуск на другой машине или в другом каталоге не может подтвердить работу CLI и GPU на целевом Windows 11/RTX 3080 Ti. Эти шаги требуют фактического запуска на Windows.

## Восстановление после «Author identity unknown» (06.11.2026)

Старый скрипт мог создать папку `.git` и добавить файлы в индекс без начального коммита. Поэтому следующая попытка показывала `initialized: false`, а потом `Git рабочее дерево изменено`. Исправленный `AI_SETUP_WINDOWS.bat` **не требует** удаления `.git`, не выполняет `git reset --hard` и не затрагивает рабочие PAPER-базы. В новой распакованной копии достаточно запустить `AI_SETUP_WINDOWS.bat`, затем `AI_CYCLE_WINDOWS.bat`. Для уже частично инициализированной копии тот же код способен продолжить инициализацию, если исходники в точности совпадают с проверенным манифестом; скопируйте обновлённые исходники целиком, не заменяя один BAT в старой папке.

## Восстановление после `codex: FileNotFoundError` (06.11.2026)

В npm на Windows команда `codex` обычно предоставляется файлом `codex.cmd`.
Старый `doctor` проверял только наличие команды в `PATH`, а запускатель вызывал
`subprocess.run(["codex", ...])` напрямую: поиск `.cmd` и создание процесса в Windows
не всегда совпадали. Поэтому `doctor` мог показать `ready_for_ai_cycle=true`,
а цикл останавливался на `codex: FileNotFoundError`.

Исправленный `doctor` запускает `codex --version` **тем же способом**, который
используется в реальном цикле. Для npm `.cmd` выполняется явный вызов через
`cmd.exe /d /s /c` с полным путём к установленному Codex. Длинное русское
задание передаётся через UTF-8 stdin (`codex exec ... -`), а не через Windows
командную строку. При сбое журнал сохраняет системную ошибку с указанием пути.

Распакуйте полный архив в новую папку. Достаточно выполнить `INSTALL.bat`,
`AI_SETUP_WINDOWS.bat`, затем `AI_CYCLE_WINDOWS.bat`; Git/Codex/Ollama уже были
обнаружены на целевом ПК, переустанавливать их не требуется. Если проверка
`codex_launch_ok` показывает `false`, причину следует искать в новом логе
`AI_SETUP_WINDOWS_LAST.log`, а не в переменных PAPER-ботов.

Эта поправка протестирована в Linux с моделью Windows CMD и отдельными
тестами CLI. **Запуск именно на вашем Windows 11 не подтверждён**, пока
не будет выполнен реальный цикл на вашем ПК.

## Запуск Codex при ошибке `codex --version: exit 1` (06.11.2026)

Прежняя версия находила `codex.cmd`, но скрывала его stderr, поэтому по `exit 1`
нельзя было отличить сломанный npm-shim от отсутствующей Node.js-зависимости
или ошибки самого CLI. Исправленная версия проверяет два способа:

1. Прямой `node.exe <npm-prefix>/node_modules/@openai/codex/bin/codex.js --version`
   (только если пакет подтверждён как `@openai/codex`).
2. Штатный `cmd.exe /d /s /c "...codex.cmd --version"`.

Выбирается **только способ с реально успешным `--version`**. После этого он же
используется для `codex exec`; автоматического повторного запуска `exec` через
другой способ после ошибки нет, чтобы не применить изменения дважды.
Полные сообщения об ошибках обоих методов сохраняются без известных шаблонов
токенов в `.ai_work/CODEX_PREFLIGHT_LAST.log` и
`.ai_work/CODEX_PREFLIGHT_LAST.json`. При повторном блокировании пришлите
именно `CODEX_PREFLIGHT_LAST.log` (после просмотра на наличие секретов): там
будет текст ошибки Node/Codex вместо одного `exit 1`. Никакие файлы рабочего
PAPER-состояния эти проверки не изменяют.

Нативная Windows-проверка этого изменения ещё не выполнена. Испытания на Linux
проверяют настоящий запуск JavaScript CLI через установленный Node и симуляцию
ветки Windows `.cmd`, но не заменяют проверку именно в Windows 11.

## Диагностика ошибок `codex exec` (6 ноября 2026)

`codex --version` доказывает только запуск CLI, **не авторизацию** и не работоспособность
генерации кода. `doctor` теперь дополнительно выполняет бесплатную команду
`codex login status`, не делая запрос к модели. Если вход не выполнен, нужно
запустить `codex login` через браузер; API-ключ в чате не передавать.
Вариант с `OPENAI_API_KEY` допускается без входа через браузер, но наличие ключа
в переменной среды ещё не означает его работоспособность.

Если при `codex exec` процесс завершится с ошибкой, окно и основной журнал показывают
последние строки реального `codex.log`, а сокращённая очищенная копия создаётся
в `.ai_work/CODEX_EXEC_FAILURE_LAST.log`. **Запуск не повторяется автоматически**,
поскольку Codex мог уже изменить исходники до отказа.
Если причина не очевидна, пришлите `codex.log` из пути, указанного в окне; журнал
`CODEX_PREFLIGHT_LAST.log` отражает только проверку `--version`, не выполнение.
Перед передачей любого журнала проверьте, нет ли в нём секретных данных.


## Когда ChatGPT Codex исчерпал лимит (06.11.2026)

`You've hit your usage limit` означает лимит подписки, а не ошибку Python или BCC.
Повторные AI-циклы с той же авторизацией не помогут до сброса лимита.

Чтобы работать раньше, можно **добровольно** выбрать отдельно оплачиваемый API:

1. Установить бюджет/ограничения расходов в OpenAI Platform самостоятельно.
   Скрипт **не обеспечивает жёсткий долларовый лимит** и не запускает платный API без выбора режима.
2. Запустить `AI_API_LOGIN_WINDOWS.bat` из папки BCC. Ввести `API` для подтверждения
   и затем ключ в скрытом вводе. Никогда не отправлять ключ в чат.
3. Проверить `AI_SETUP_WINDOWS.bat`: должно быть `codex_auth_mode: api` и
   `codex_login_ok: true`. Затем `AI_CYCLE_WINDOWS.bat`.
4. Для возвращения на авторизацию ChatGPT запустить `AI_USE_CHATGPT_WINDOWS.bat`.

API-авторизация хранится отдельно от ChatGPT в каталоге пользователя
`%LOCALAPPDATA%\BCC_Codex_API`, **вне Git и архивов проекта**. Там могут быть
учётные данные; не пересылайте содержимое этого каталога.
`codex login status` проверяет наличие авторизации, но не наличие средств,
право доступа к выбранной модели и не гарантирует успех платной генерации.
В режиме ChatGPT скрипт игнорирует случайно унаследованный `OPENAI_API_KEY`,
чтобы не тратить API-бюджет незаметно. В API-режиме ключ передаётся при
однократной настройке через stdin без записи в команду или Git.

Если ChatGPT показывает `try again at Nov 11th, 2026 11:45 AM`, время сброса
определяется сервером Codex; не нужно менять системное время.

Если API не выбран, можно использовать Ollama локально для независимого анализа,
но это **не заменяет полноценное исполнение комплексного задания Codex**.


## Однократный приватный API bootstrap

Если пользователь явно заказал персональную копию архива с тестовым ключом,
он помещается только в `.ai_work/.codex_api_key_once`, исключённый из Git
и SHA-256 манифеста исходников. `AI_SETUP_WINDOWS.bat` или
`AI_CYCLE_WINDOWS.bat` перед остальными действиями выполнит `codex login
--with-api-key` через stdin. После успешного входа файл удаляется,
а авторизация хранится в `%LOCALAPPDATA%/BCC_Codex_API`.

**Архив, содержащий ключ, сам является секретом.** Его нельзя публиковать,
отправлять третьим лицам или сохранять в общедоступном облаке. Ключ можно
отозвать после проверки. Это не гарантирует бюджет $5 и не запускает
торговлю; платные вызовы начинаются только после явного запуска AI CYCLE.

## Проверка реальных прав записи Codex и повторное использование API (06.11.2026)

Если `Codex не изменил исходники`, наличие `codex --version` и `codex login status`
не означает возможность модификации репозитория. Следующий цикл **сначала** выполняет
короткий проверочный модельный вызов и просит Codex записать строго определённый
текстовый файл в игнорируемую папку `.ai_work/<run_id>`. Проверяется фактическое
содержимое файла и отсутствие изменений в Git; файл удаляется при успехе.
Это **платный API-вызов**, если выбран API, и он не гарантирует лимит расходов.
При невозможности записи основной большой промпт не отправляется; диагностическая
причина будет в `codex_write_probe.log` и `write_probe_failure.json`.

Если проверка записи прошла, но Codex не внёс изменений, работа не засчитывается,
а последние строки `codex.log` и причина сохраняются в `CODEX_NO_CHANGES_LAST.log`.
Скрипт не выполняет автоматическую платную повторную попытку.

**Новый архив не содержит API-ключа.** После одноразовой настройки ключ и
авторизация уже находятся в `%LOCALAPPDATA%/BCC_Codex_API`. Чтобы снова
использовать их в *новой папке BCC* без ввода ключа, запустите
`AI_USE_EXISTING_API_WINDOWS.bat` — это явное разрешение на будущую отдельно
оплачиваемую работу. Затем `AI_SETUP_WINDOWS.bat` и `AI_CYCLE_WINDOWS.bat`.
Не переносите файл временного ключа из старого архива в новый.
Нативная Windows проверка прав записи должна быть подтверждена локальным запуском.


## Реальный отказ `sandbox: read-only` при `workspace-write` (06.11.2026)

Если `codex login status` успешен, но в `codex_write_probe.log` указан
`sandbox: read-only`, авторизация и права изменения файлов — **разные проверки**.
Codex теперь запускается с явными `--sandbox workspace-write` и
`-c sandbox_mode="workspace-write"` в рамках каталога BCC. Проверка требует
фактической записи уникального файла, проверки его содержимого и удаления.
Если установленный Codex или системная политика по-прежнему принудительно
выбирает `read-only`, цикл завершается как BLOCKED без повторных API-вызовов
и без автоматического расширения доступа до `danger-full-access`.

**Это исправление не подтверждено на вашем Windows:** необходим реальный запуск
`AI_SETUP_WINDOWS.bat`, затем `AI_CYCLE_WINDOWS.bat` в новой распакованной папке.
Не переносите `.git`, `.ai_work`, ключи API или PAPER-базы из старой папки.
Для повторного использования API-авторизации из локального профиля
выберите `AI_USE_EXISTING_API_WINDOWS.bat`; ключ в архив добавлять не нужно.
